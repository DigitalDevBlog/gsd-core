<objective>
## Goal
Wire diagram-as-code rendering into the site via `mkdocs-kroki-plugin==0.9.0`, so any
content page can embed PlantUML or Excalidraw diagrams from fenced source blocks.

## Purpose
Every content phase (2-9) explains structure. Structure needs diagrams. Establishing the
rendering path once, in the foundation phase, means content plans never have to think
about tooling.

## Output
- `requirements.txt` — Kroki plugin pinned
- `mkdocs.yml` — `plugins:` block with `search` + `kroki`
- `learn/diagrams.md` — an authoring reference proving each engine renders (kept out of nav)
</objective>

<context>

## Known constraints
- The plugin is pinned to 0.9.0 by project decision: v1.x pulls a `properdocs` dependency
  that injects advertising into builds.
- Declaring a `plugins:` block overrides MkDocs' implicit `[search]` default — `search`
  must be listed explicitly or site search silently disappears.
- Kroki renders by POSTing diagram source to a server. Default is the public kroki.io,
  so a strict build requires network access.
</context>
