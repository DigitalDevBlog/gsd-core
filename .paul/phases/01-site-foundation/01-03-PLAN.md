<objective>
## Goal
Wire `mike`-based documentation versioning into the site so docs can be published per
GSD Core release with an Antora-style version switcher, without performing a deploy.

## Purpose
PROJECT.md lists "Docs versioned per GSD Core release, switchable in the site" as a
success metric. GSD Core is at v1.11.0 and moving; docs that do not say which version
they describe go stale invisibly.

## Output
- `requirements.txt` — `mike` added
- `mkdocs.yml` — `extra.version.provider: mike`
- Deploy procedure documented for the user to run
</objective>

<context>
## Project Context
@.paul/PROJECT.md

## Prior Work
@.paul/phases/01-site-foundation/01-01-SUMMARY.md

## Deliberate scope decision
`mike deploy` commits the built site to a `gh-pages` branch of this repo — a real,
published package repo currently on branch `next`. Creating or pushing that branch is the
repo owner's call, not this plan's. This plan therefore configures versioning and
documents the command; it does not execute a deploy.
</context>
